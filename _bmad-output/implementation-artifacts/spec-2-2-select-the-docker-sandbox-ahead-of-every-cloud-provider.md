## Intent

**Problem:** `src/mastra/index.ts:302-325` selects a sandbox as Platform → E2B → local, pinning local only
on the exact string `local`. So `FACTORY_SANDBOX_PROVIDER=docker` does nothing, and a stray
`MASTRA_PROJECT_ID` / `MASTRA_ENVIRONMENT_ID` / `E2B_API_KEY` silently relocates agent work off this Mac.
The image Story 2.1 built has nothing that can ask for it, and `@mastra/docker` is not installed.

**Approach:** Install `@mastra/docker`, and add a `DockerSandbox` branch **ahead** of the whole existing
chain so the guarantee is structural rather than a matter of keeping `.env` clean. The branch is keyed by
session id and carries hard ceilings from env. Declare the sandbox key group in `.env.schema`, and correct
the four committed sentences that say the branch has not landed yet.

## Boundaries & Constraints

**Always:**
- The `docker` branch is the **first** statement in the `sandbox:` callback — before `hasPlatformSandboxEnv`
  and before `E2B_API_KEY` are consulted at all (FR3 / NFR12).
- `FACTORY_SANDBOX_PROVIDER` is read at exactly one site and compared after `.trim()`. Any value that is
  neither `docker` nor `local` falls through to the existing chain unchanged — never throws (NFR23).
- Ceilings come from env with the defaults the epic names: `memory` = `FACTORY_SANDBOX_MEMORY_GIB` (10) in
  bytes, `cpuQuota` = `FACTORY_SANDBOX_CPUS` (4) × `cpuPeriod` 100 000 µs, `pidsLimit` 4096, `timeout`
  15 min, `workingDirectory` = `MASTRACODE_SANDBOX_WORKDIR` (`/workspace`).
- `workingDirectory` — the base-class option — never the package's deprecated `workingDir`.
- `id: ctx.sessionId`, so Factory's id-keyed get-or-create on `start()` reattaches rather than recreates.
- The literal `new Mastra(...)` stays in `src/mastra/index.ts` (AD-2 / NFR1); the diff is small and
  commented because the entry now diverges from the upstream template.
- Each new env key is read at exactly one site, and declared in `.env.schema` (the only list of keys) and
  mirrored into `.env.example`.
- The installed `@mastra/docker` version is re-verified against `@mastra/core@1.67.0`'s peer range and the
  version actually resolved is recorded — `0.8.0` is inherited intent, not a pin (NFR20).

**Never:**
- Never move construction out of the entry into a config module — Epic 5 owns that (NFR21).
- Never restate in `sandbox/README.md` the half `.env.schema` owns: no required/optional, no sensitivity,
  no `@public`, no `@type` (NFR7). Conversely, never put "what the value must contain / how to obtain it"
  prose into `.env.schema` beyond the one-line orientation its existing entries carry.
- Never edit `docker-compose.yml`, `tsconfig.json`, `AGENTS.md`, `README.md`, `docs/`,
  `sandbox/factory-sandbox.Dockerfile`, or `.bmad-loop/policy.toml`. `docs/` section numbers are stable
  citation anchors (Story 5.3 owns that file); `policy.toml` is gitignored orchestrator surface.
- Never add a dependency the code does not import, and never install a second copy of `@mastra/core`.
- Never run `docker` or `colima`, and never require a reachable daemon: nothing here starts a container.

## Design Notes

**Why the helper, and why it is exported.** The ceilings are the part of this story that can actually be
wrong — a `cpuQuota` computed against the wrong period, or a memory number in GiB where bytes were meant,
is invisible until a session either ignores its cap or is OOM-killed instantly. Nothing else in this
repository can observe a `DockerSandboxOptions`, so the options are built by one exported function and
asserted in `index.test.ts`, exactly as `positiveInt` and `localSandboxEnv` already are. The branch itself
stays three lines in the callback, which is what keeps the entry diff small (AD-2).

```ts
if (sandboxProvider === 'docker') return new DockerSandbox(dockerSandboxOptions(ctx.sessionId));
```

**Why an unset image refuses instead of defaulting.** `DockerSandboxOptions.image` defaults to
`node:22-slim`, which ships neither `git` nor `gh` — the exact condition Story 2.1 exists to prevent, and
one Factory reports as `git-missing` only after a session has already started. There is no honest default:
the only correct image is a tag someone built on this host. The slot is called per session, so throwing
names the missing key at the first session rather than taking the deployment down at boot. Defaulting to
`factory-sandbox:2026-09-22` as `docs/` §2.2 sketches is worse — that tag was never built anywhere.

**Why `positiveInt` rather than `Number(x) || 10`.** `Number('') || 10` and `Number('abc') || 10` both give
10, but so does `Number('-4') || 10` silently, while `Number('2.5')` yields a fractional quota nobody
documented. `positiveInt` already rejects non-positive, fractional and unsafe values with tests behind it,
so "whole number, anything else means the default" is one rule stated once — and `sandbox/README.md`
already says "a whole number" for both keys.
