## Intent

**Problem:** `src/mastra/index.ts:141-155` picks auth as disabled → platform (`MASTRA_SHARED_API_URL`) →
WorkOS → nothing. The self-managed arm is WorkOS, a hosted external IdP, and the fall-through arm hands
identity to `MastraAuthStudio` pointed at `https://platform.mastra.ai/v1`. So this deployment cannot
authenticate anybody without reaching a third party, and `@mastra/auth-better-auth` is not installed.

**Approach:** Install `@mastra/auth-better-auth` and replace the WorkOS arm with `MastraAuthBetterAuth`
constructed in deferred-instance mode — `secret` only, no `auth` instance — so the provider builds its own
`betterAuth()` against the handle `MastraFactory` already passes it from `storage.authDatabase?.()`, on this
deployment's own Postgres, and installs the `organization()` plugin itself. Extract the whole chain into an
exported `selectAuth()` so the *order* is reachable from a test, declare `BETTER_AUTH_SECRET` in
`.env.schema`, and correct the committed sentences that name WorkOS as the self-managed path.

## Boundaries & Constraints

**Always:**
- The provider is constructed in **deferred-instance mode**: `{ secret, signUpEnabled: true }` and nothing
  else. `signUpEnabled: true` is explicit and carries a comment naming Story 2.6 as the story that flips it.
- `BETTER_AUTH_SECRET` is read at exactly one site, trimmed, and a blank/unset value means "not configured"
  — the branch is skipped, exactly as the WorkOS group is skipped today. It must never reach the
  constructor: `new MastraAuthBetterAuth({})` throws at module load (see Design Notes).
- Branch order is preserved verbatim: `MASTRACODE_AUTH_DISABLED=1` → `null`; then `MASTRA_SHARED_API_URL`
  → leave `undefined` (platform), warning when a self-managed secret is also set; then Better Auth; then
  `undefined`. The chain moves into an exported `selectAuth()` so a test can observe the order.
- `const secretEncryption = auth === null ? undefined : credentialEncryption()` keeps its exact meaning —
  `MASTRACODE_AUTH_DISABLED=1` is the only value that drops credential encryption.
- `BETTER_AUTH_SECRET` is declared in `.env.schema` (the only list of keys) marked `@sensitive`, never
  `@required` — an unconditional `@required` fails the verify gate's `npx varlock load`, which runs with no
  `.env` present. Mirrored into `.env.example` as a commented-out assignment.
- The literal `new Mastra(...)` stays in `src/mastra/index.ts` (AD-2 / NFR1); the diff is small and
  commented because the entry now diverges from the upstream template.
- The installed `@mastra/auth-better-auth` version is re-verified and the version actually resolved is
  recorded — `1.1.5` is inherited intent, not a pin (NFR20).

**Never:**
- Never add `better-auth`, `hono`, `kysely` or any other package to `package.json`: the code imports none of
  them. `@mastra/auth-better-auth` carries its own `better-auth`, and a second root copy would produce two
  `Auth` realms.
- Never pass `auth:`, `baseURL:`, `database:`, `plugins:` or `organization()` — none is a constructor option
  on this provider, and a bring-your-own `auth` instance skips the plugin, the migrations and the
  `basePath`. Never set `name:` — the SPA renders the email/password form only for the literal
  `"better-auth"`.
- Never introduce `BETTER_AUTH_URL`: the provider sets `baseURL` from the factory's `publicUrl`, which this
  entry already wires from `MASTRACODE_PUBLIC_URL` (`src/mastra/index.ts:460`).
- Never remove `WORKOS_COOKIE_PASSWORD` from the `stateSecret` fallback chain (`src/mastra/index.ts:401-405`)
  and never delete the `WORKOS_*` declarations from `.env.schema` / `.env.example` — only their prose
  changes.
- Never set `MASTRA_SHARED_API_URL`, `WORKOS_*` or `MASTRACODE_AUTH_DISABLED` anywhere in the repo, and
  never add `MASTRACODE_AUTH_DISABLED` to `.env.schema` (NFR12; it is deliberately undeclared).
- Never edit `docs/`, `AGENTS.md`, `docker-compose.yml`, `tsconfig.json`, `sandbox/`, `ops/`,
  `.bmad-loop/policy.toml` or `sprint-status.yaml`. `docs/Self-hosting research.md` section numbers are
  stable citation anchors and Story 5.3 owns that file.
- Never move construction into a config module — Epic 5 owns that (NFR21). Never start a server, open a
  database connection, or run a migration: the provider's migrations are lazy and fire on first request.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Self-managed sign-in | `BETTER_AUTH_SECRET=<32+ chars>`, nothing else set | a `MastraAuthBetterAuth` whose `name` is `better-auth` and whose `isSignUpEnabled()` is `true` | No error expected |
| Padded secret | `BETTER_AUTH_SECRET=" s3cret… "` | trimmed before construction, so the branch is still taken | No error expected |
| Secret unset or blank | `BETTER_AUTH_SECRET` unset, `""` or `"   "` | `undefined` — falls through unchanged, exactly as an unset `WORKOS_*` group does today | No throw: the constructor is never reached |

| Platform alone | `MASTRA_SHARED_API_URL` set, no secret | `undefined`, and **no** warning | No throw |
| Auth off | `MASTRACODE_AUTH_DISABLED=1` with every other auth var set | `null`, and `secretEncryption` is `undefined` | No throw |
| WorkOS residue | `WORKOS_API_KEY` + `WORKOS_CLIENT_ID` set, no `BETTER_AUTH_SECRET` | `undefined` — the entry no longer wires WorkOS at all | No throw |
| Nothing configured | no auth var set | `undefined`, unchanged from today | No throw |

## Design Notes

**Why a blank secret must be gated, not passed.** `MastraAuthBetterAuth`'s constructor throws when both
`auth` and `secret` are falsy (`dist/index.js:439`), and the message — *"Better Auth instance is
required…"* — names the wrong cause for an operator who simply forgot `BETTER_AUTH_SECRET`. The throw
happens at module load, so it takes the whole deployment down at boot. The existing WorkOS arm already
solves this shape by gating on a configured group (`workosConfigured`, line 142), and `credentialEncryption()`
(line 70) gates the same way on a blank key. So the Better Auth arm gates on a trimmed non-empty secret and
otherwise falls through — an unconfigured provider never blocks boot.

**Why falling through stays silent.** When no secret is set the chain lands on the factory's
platform-backed `MastraAuthStudio`, which is the zero-dependency mandate's worst case. It is also exactly
today's behaviour with `WORKOS_*` unset, and adding a new boot-time warning is new behaviour rather than a
correction — Story 2.2's review rejected an equivalent "log the selected provider" finding on that ground.
The one warning this story keeps is the existing one: self-managed credentials present but overridden by
`MASTRA_SHARED_API_URL`, now naming `BETTER_AUTH_SECRET` instead of the WorkOS pair.

**Why `selectAuth()` is exported.** The branch order is the guarantee — that a stray `MASTRA_SHARED_API_URL`
still wins, and that nothing else can. Module-level `if/else` statements are invisible to `vitest`, so the
chain becomes one exported function reading its own env, exactly as Story 2.2 exported `selectSandbox` to
make the Docker branch's position assertable. Unlike `selectSandbox` there is no parameter to thread:
every input is an env read, and each stays a single site inside the function.

```ts
// 3. BETTER_AUTH_SECRET — identity this deployment owns. Deferred-instance
//    mode: MastraFactory calls init() with storage.authDatabase?.(), so the
//    provider builds betterAuth() on the SAME Postgres and connection string
//    as the app tables, and installs organization() itself.
const betterAuthSecret = process.env.BETTER_AUTH_SECRET?.trim();
if (betterAuthSecret) {
  // Story 2.6 flips this to false once the single account exists.
  return new MastraAuthBetterAuth({ secret: betterAuthSecret, signUpEnabled: true });
}
```

**Why `signUpEnabled: true` is written even though it is the default.** `@default true`
(`dist/index.d.ts:40`) makes the literal inert today, but Story 2.6's acceptance criterion is that closing
registration is *a committed, reviewable diff* rather than an env toggle. A field that already exists turns
that story into a one-character change with a clear blame line; an absent field would make it an addition
whose default nobody wrote down.
